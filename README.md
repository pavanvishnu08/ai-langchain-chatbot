# LangChain vs. Normal Chatbot — ORX AI Demo

A Streamlit app that lets you type one question and see it answered **two
ways at once**, using the same LLM:

- **Normal chatbot** — a direct LLM call. Answers from whatever it learned
  during pretraining. No access to any ORX-specific data or tools.
- **LangChain chatbot** — a tool-calling agent that retrieves from a
  synthetic ORX AI demo knowledge base (RAG), and can also look up
  products, customer accounts, and support tickets, or escalate — choosing
  whichever fits the question.

**Total cost: $0.** Embeddings and vector search run locally and free. The
LLM call uses Groq's free API tier (or a fully local, offline Ollama model).

> **Note:** All data in this project (`orx_ai_demo_mock_data/`) is
> entirely synthetic — created for this demo. It is **not** real ORX
> data, **not** patient data, and nothing here is medical advice.

## 1. Installation guide

### Prerequisites

- Python 3.11 (or 3.10+)
- A free [Groq API key](https://console.groq.com/keys) — no credit card needed

### Step 1 — Get the code and open a terminal here

```bash
cd ORX-langchain-demo
```

### Step 2 — Create an isolated virtual environment

Strongly recommended: this project's dependencies (torch, transformers,
sentence-transformers) can conflict with other packages already installed
globally on your machine. A project-local venv avoids that entirely.

**Windows (PowerShell / Git Bash):**
```bash
python -m venv .venv
./.venv/Scripts/python.exe -m pip install --upgrade pip
```

**macOS / Linux:**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
```

### Step 3 — Install dependencies

```bash
# Windows
./.venv/Scripts/python.exe -m pip install -r requirements.txt

# macOS / Linux (with venv activated)
pip install -r requirements.txt
```

This installs Streamlit, LangChain, the Groq/Ollama/HuggingFace
integrations, FAISS, and sentence-transformers. First install takes a
few minutes (torch is a large download).

### Step 4 — Configure your API key

```bash
cp .env.example .env
```

Open `.env` and fill in:

```
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_your_key_here
```

Get a free key at https://console.groq.com/keys (no credit card).

> Prefer to run fully offline instead? Install [Ollama](https://ollama.com),
> run `ollama pull llama3.1 && ollama serve`, and set `LLM_PROVIDER=ollama`
> in `.env` instead. See `config.py` for details.

### Step 5 — Build the vector index

```bash
# Windows
./.venv/Scripts/python.exe build_knowledge_base.py

# macOS / Linux
python build_knowledge_base.py
```

This reads `orx_ai_demo_mock_data/knowledge_base/*.json`, embeds each
record locally (free, downloads a small ~90MB model on first run), and
saves a FAISS index to `vectorstore/`. Re-run this any time you edit the
mock data.

### Step 6 — Launch the app

```bash
# Windows
./.venv/Scripts/python.exe -m streamlit run app.py

# macOS / Linux
streamlit run app.py
```

Open the local URL Streamlit prints (usually http://localhost:8501), type
a question, and compare the two answers.

## 2. Project structure

```
ORX-langchain-demo/
├── orx_ai_demo_mock_data/       # synthetic dataset (see its own README.md)
│   ├── knowledge_base/             # products, FAQ, accessories, safety, policies, troubleshooting
│   ├── customers/customer_profiles.json
│   └── support/support_tickets.json
├── vectorstore/                    # generated by build_knowledge_base.py (FAISS index)
├── config.py                       # LLM provider/model selection (Groq or Ollama)
├── tools.py                        # LangChain tools used by the agent chatbot
├── build_knowledge_base.py         # one-time step: JSON -> chunks -> embeddings -> FAISS
├── normal_chatbot.py                # plain LLM chatbot, no retrieval, no tools
├── rag_chatbot.py                   # standalone fixed-step RAG chatbot (CLI example)
├── agent_chatbot.py                 # LangChain tool-calling agent (RAG + tools)
├── app.py                           # the Streamlit UI (Normal vs. LangChain agent)
├── .env.example                     # copy to .env and fill in your key
└── requirements.txt
```

## 3. How the LangChain chatbot works

Instead of a single hardcoded retrieval step, the agent (`agent_chatbot.py`)
picks whichever tool fits the question, possibly chaining several:

| Tool | Purpose |
|---|---|
| `search_knowledge` | FAISS search over products/FAQ/accessories/safety/policies/troubleshooting |
| `get_product` | Exact product lookup by name |
| `lookup_customer` | Exact customer account lookup by ID (e.g. `C001`) |
| `search_support_tickets` | Filter support tickets by customer/product/issue |
| `escalate_to_support` | Simulated hand-off for clinical/safety/unresolved requests |

```
Your question
     │
     ▼
Agent (LLM) decides which tool(s), if any, to call
     │
     ├─ search_knowledge ──► embed question → FAISS search → top matches
     ├─ get_product ────────► exact lookup in products.json
     ├─ lookup_customer ────► exact lookup in customer_profiles.json
     ├─ search_support_tickets ► filtered lookup in support_tickets.json
     └─ escalate_to_support ──► simulated escalation acknowledgment
     │
     ▼
Agent answers using ONLY what the tool(s) returned, or says it doesn't know
```

The normal chatbot skips all of this — it just sends the raw question
straight to the LLM, so it has zero access to any of the above.

## 4. Switching models

The sidebar has a **🧠 Model** dropdown (Groq models, configured in
`config.py`'s `GROQ_MODELS` list). Both chatbots rebuild automatically
with the newly selected model — no restart needed. Add more models to
that list to offer more choices.

## 5. Why this is a good teaching demo

Ask both bots *"Show the support history for C001"* or *"Has C001 reported
a mask leakage issue?"* — the normal chatbot has no way to know this and
will dodge or invent an answer. The LangChain chatbot calls
`search_support_tickets`, retrieves the real (synthetic) ticket records,
and answers correctly — expand **🛠️ Tools called** / **📚 Retrieved from
these sections** in the UI to see exactly what it used. That's the core
idea behind RAG and tool-use: **traceable, checkable answers.**

## 6. Customizing / extending

- **Add more knowledge:** add records to the JSON files under
  `orx_ai_demo_mock_data/knowledge_base/`, then re-run
  `build_knowledge_base.py`.
- **Add more tools:** define a new `@tool`-decorated function in
  `tools.py` and add it to `ALL_TOOLS`.
- **Add more models:** edit `GROQ_MODELS` in `config.py`.
- **Swap providers entirely:** set `LLM_PROVIDER=ollama` in `.env` to run
  fully offline.

## 7. Troubleshooting

- **`ImportError` / `torch has no attribute 'compiler'` when building the
  knowledge base:** your global Python environment has conflicting
  torch/transformers/protobuf versions. Use the project's `.venv` (Step
  2–3 above) instead of a global Python install.
- **`GROQ_API_KEY not set` in the sidebar:** make sure `.env` exists
  (copied from `.env.example`) and has your key, then restart the app.
- **`No vector index yet` warning:** run `build_knowledge_base.py` first.

## 8. Important notes

- `orx_ai_demo_mock_data/` is entirely synthetic and was created only
  for this LangChain/RAG/agent demonstration. It is **not** official
  ORX data and **not** patient data — see its own `README.md`.
- Nothing here should be used to give medical advice. The assistant is
  instructed to defer diagnosis/treatment/clinical requests to a
  qualified professional and to escalate rather than guess.
- Groq's free tier is generous but rate-limited. For a fully offline,
  rate-limit-free option, use Ollama (see Step 4).
